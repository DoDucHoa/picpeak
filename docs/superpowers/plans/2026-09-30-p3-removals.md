# P3 Removals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the features and per-event copies the redesign retires (guest uploads, reveal mode, event start and end time in the UI, per-event keyboard shortcuts, per-event hero logo size and position, per-event password page logo, "require admin email"), and add the one global notification email that replaces the per-event admin address.

**Architecture:** Everything is removed in code, never by a data migration: the columns keep their values, the gallery resolvers stop reading them, the admin APIs stop writing them, and the admin UI stops showing them, so a rollback is a code revert. New global values come from `app_settings` keys, read with `decodeSettingValue` / `readBooleanSetting` (values are stored multiply JSON encoded). One small service resolves the admin address for every event mail and payload.

**Tech Stack:** Node/Express + knex, Jest + supertest (`bootCrmDb`); React 18, TanStack Query, Vitest + Testing Library, i18next; Playwright.

**Spec:** `docs/superpowers/specs/2026-09-28-event-form-redesign-design.md`: 3 (decisions), 4 findings 8, 10, 11, 12, 5.10, 5.11, 5.12, 5.13, section 6 "P3", section 8.

## Global Constraints

- Removed in code, not by a data migration (spec 5.12): "the columns keep their values, so rollback is a code revert". Response shapes stay compatible: a field that stops meaning anything is still returned (spec 2 non-goals), with its neutral value.
- "Ignored" means both gallery resolvers (`routes/gallery/metadata.js`, `services/galleryQueryService.js`) resolve the value from the global setting; the event column is left untouched and still returned (spec 5.10).
- Each new key is added wherever its settings route keeps an explicit key list, and seeded by a migration (spec 5.10). New migrations are numbered above upstream's highest (upstream ends at 256, this branch at 258): P3 uses 259 and 260.
- Resolution for every admin address tied to an event: the global value when set, otherwise the event's `admin_email`, otherwise skip, as today (spec 5.11).
- `general_notification_email` is validated as an email on the server and kept off the public settings whitelist (spec 5.11).
- Workflows, approvals, invoices and contracts keep using `business_profile.email` (spec 5.11).
- Every new user-facing string gets `en`, `de` and `vi` in the same change; German admin copy uses "du". Existing keys are never pruned. Copy that mentions removed features is rewritten (spec 5.13).
- No em-dash (U+2014) or en-dash (U+2013) in anything written into the repo, moved upstream comments included. Conventional Commits.
- `backend/jest.setup.js` keeps its `DATABASE_CLIENT` pin. Backend Jest from `backend/`, Vitest from `frontend/`. Never edit while a background test run is in flight. Git as plain single commands.
- Nothing is deployed in this phase (rule D5).

## Rulings made while writing this plan (the spec predates them)

1. **Uploader names split in two.** The name mode (`guest_name_mode`: off, optional, required) only decides what the guest upload dialog asks, so its control goes everywhere (event page, create page, Settings > Event Defaults). The "show names to guests" switch (`show_credits_to_guests`) also governs photographer credits read from EXIF (`galleryQueryService` `credits_visible`), so it stays, as a standalone `CreditVisibilitySetting` with copy about photo credits. The backend keeps accepting `guest_name_mode` (nothing reads it without uploads).
2. **Guest registration and the Guests tab are left as they are.** Both still open for an old event whose stored columns had uploader names on (`galleryGuests.js` `uploaderNamesOn`, `eventHasGuests`). That keeps existing uploader guests, and their names on photos, manageable and erasable. With the upload dialog gone, nothing in the gallery asks a guest to register for uploads. Cost if wrong: a guest of such an event could still register a name through the API that nothing uses.
3. **The guest upload route becomes one handler that answers 403**, and the upload processing status route goes with the frontend poller that was its only caller. `galleryUploadLimits.test.js` tests only the removed route and is deleted; `galleryUploadStatus.test.js` keeps its cache-header half and gains the removal pins.
4. **Reveal mode keeps its module.** `utils/revealMode.js` is the single choke point of every gate and three suites mock it, so `isGalleryHidden` returns false and the exports stay. The scheduler file is deleted with its start and shutdown entries. `POST /admin/events/:id/reveal` is deleted; the CSRF pin that used it moves to `POST /:id/toggle-status`.
5. **The `gallery.revealed` trigger stays in the workflow editor's list.** A saved workflow may name it, and removing it would blank that workflow's trigger on the next edit. It simply never fires. Usage telemetry keeps reporting from the stored columns, which is true data.
6. **The payload flags keep their names with neutral values**: `/photos`, `/info` and the gallery login send `allow_user_uploads: false`; `/photos` sends `reveal_armed: false` and `hidden_until_reveal: false`. An open browser tab running the old bundle therefore also hides its upload button.
7. **Event start and end time exist only on the create page** (the event page never had them). The backend keeps accepting them as optional; omitting them already means "full day".
8. **Keybind reads one key.** `getEventFeedbackSettings` overrides `keybind_mode` with the global value on every return, with and without a row. The feedback PUT stops writing the column (dropped from `FEEDBACK_SETTINGS_COLUMNS`); create keeps writing its dormant copy, which nothing reads. The global control in Settings > Events leaves the "defaults for new galleries" block, since it now applies to every gallery at once. `parseKeybindModeSetting` decodes every JSON layer.
9. **Hero logo size can be `custom` globally.** Events with a NULL size already received `custom`; now every event does. `GalleryLayout` honours it and `HeroHeader` falls back to its medium classes, as it already does for those events. Left as is and named in the report.
10. **Duplicate keeps copying `hero_logo_position`.** The column is dormant and has a database default of `top`; "create stops writing" is honoured by the create service, which all three create paths share.
11. **The admin address row leaves the event Overview.** Spec 5.1 lists no admin address on the Overview, and the stored value no longer decides who gets mail when the global is set. The archive details API and the event list search keep reading the stored column (historical record, search).
12. **The conversions drop both fallbacks.** Quote and contract conversions store the global value, else the acting admin's address, else NULL (the column is nullable since migration 073). `admin@picpeak.local` was a mailbox nobody reads; NULL skips the mail, which is the spec's "otherwise skip".
13. **The `event_require_admin_email` row is deleted by migration 260**, with a `down` that restores it, so no dead key stays in the database.
14. **The gallery.* workflow payloads carry the resolved address**, as spec 5.11 asks. Approvals and admin-class sends on those flows read `ctx.vars.adminEmail` first, so for gallery flows they follow the global address too. Invoice and quote flows are unaffected.

function parseKeybindModeSetting(rawValue) {

```js
// backend/src/services/notificationEmail.js
/**
 * The admin address for everything tied to an event (P3 of the event form
 * redesign, spec 5.11): the global notification email when it is set,
 * otherwise the event's own admin_email, otherwise none, and the mail is
 * skipped as before. Workflows, approvals, invoices and contracts keep using
 * business_profile.email.
 */
const validator = require('validator');
const { db } = require('../database/db');
const logger = require('../utils/logger');
const { decodeSettingValue } = require('./eventSettings');

const NOTIFICATION_EMAIL_KEY = 'general_notification_email';

/** The global address, trimmed and valid, or null. Never throws. */
async function getNotificationEmail(conn = db) {
  try {
    const row = await conn('app_settings').where('setting_key', NOTIFICATION_EMAIL_KEY).first();
    const value = row ? decodeSettingValue(row.setting_value) : null;
    const address = typeof value === 'string' ? value.trim() : '';
    return address && validator.isEmail(address) ? address : null;
  } catch (error) {
    logger.error('Failed to read the notification email', { error: error.message });
    return null;
  }
}

/** Global address, else the event's own, else null. */
async function resolveAdminEmail(event, conn = db) {
  const global = await getNotificationEmail(conn);
  if (global) return global;
  const own = typeof event?.admin_email === 'string' ? event.admin_email.trim() : '';
  return own || null;
}

module.exports = { NOTIFICATION_EMAIL_KEY, getNotificationEmail, resolveAdminEmail };
```
